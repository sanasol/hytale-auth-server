Minimal compatibility inference for observed missing-accept issue:
After successful gateway.connected, emit accepted notifications for authenticated user's CURRENT persisted friendships (peer UUID + stored since), through ordinary notification envelope. Existing client entries skip as duplicate; missing client entries are appended. Then ordinary presence snapshot/notifications provide online metadata. This is additive resync, NOT complete state reconciliation: it cannot delete locally stale friendships removed while disconnected, and does not replay pending incoming requests/blocks/party membership. Don't claim global resync solved by this alone. A durable ordered event replay can cover missed deletions but no client cursor/ack mechanism was observed in connection path, so server must choose replay policy independently. Snapshot must be read from current authorized state, not blindly send historical accept events for relationships later deleted.
